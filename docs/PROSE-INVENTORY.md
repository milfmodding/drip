# Prose inventory — what a human has to write before release

**For Sophia.** Gate 1 says every word a player or author reads is written by her. This is the
scoped list, so the obligation is a plan rather than a wall.

Everything here is **measured, not estimated** — counted from the files by script. Where a
number is a template count rather than a file count, it says so, because those differ by two
orders of magnitude and only one of them is work.

---

## The finding that shrinks this by more than half

**All 276 item names, and every description and short name, are already Colette's and Amber's
words.** The converter carried them through untouched.

Verified rather than assumed: comparing each converted config against its 3.x source, **275 of
276 names are byte-identical and none differ.** The one exception is
`COMBAT_PANTS_URBANREED_BOTTOM`, which had no matching source *filename* because of the
deliberate `- Copy` rename — its text is identical too, checked separately. So it is **276 of
276**.

The same is true of every quest string in `CustomLocales/en.json`.

**So ~772 of the ~940 human-readable strings in the shipped mod already pass Gate 1**, and they
are the ones players actually read. Nothing needs rewriting there. It is worth Sophia knowing
this before she looks at the totals below, because "276 item descriptions" reads like a month
and is in fact zero.

| Already theirs — no action | strings | words |
|---|---|---|
| Item `name` (276), `shortName` (140), `description` (140) — in the configs | 556 | ~6,600 |
| Quest text — `CustomLocales/en.json` | 216 | ~6,100 |

## Two things worth saying plainly

**The mock-up problem is real and it is not solved by rewriting later.** If Colette picks a
quest format tomorrow, she is picking between prose we wrote. The *design* can survive being
ours — a list of objectives with the text attached is a structure, not a sentence. The
scaffolding comments cannot, and they should be rewritten before that format ships. Choosing
the shape and writing the words are separable, and only the second is gated.

**Suggested order, by how many people read it per word written:**

1. The 6 config comment templates — 1,445 rendered lines, read constantly
2. The 32 diagnostics — read when someone is stuck
3. `README.txt` — read once per player, and by the moderators
4. `AUTHORING.md`, `REVIEWING-PRICES.md`
5. `Setup.cmd` / `bootstrap.py` / spreadsheet strings — read once each

## Gate 2 — see `CHECK-REGISTRY-DESIGN.md`

Sophia's ruling: the three technical documents above are **Gate 2 material, not Gate 1** — she
does not need to have written them, she needs to be able to answer questions from them. That is
why the in-scope figure on this page is ~3,300 words rather than ~15,000.

The Gate 2 *demonstrator* is the check registry, which has its own notes in
[CHECK-REGISTRY-DESIGN.md](CHECK-REGISTRY-DESIGN.md). One thing from there belongs here: **do
not rewrite the diagnostic wording and restructure the code in the same pass.** Gate 1 has
Sophia rewriting all 32 messages; a behaviour-preserving refactor stops being verifiable the
moment the strings change. Wording first or structure first, not both.
